# Переводы, приветствие и обзоры обновлений

Изменения подготовлены для локального просмотра. Публикация на рабочий сайт и отправка в GitHub выполняются отдельно.

## Что изменилось

- Русский и казахский интерфейс используют локальный словарь `public/i18n-catalog.js`. Внешние сервисы при переключении языка не вызываются. Локализуются статические подписи, формы, подсказки, статусы и сообщения об ошибках; пользовательский текст и значения, отправляемые серверу, сохраняются.
- Выбранный язык восстанавливается после перезагрузки. При его смене сохраняются заполненные поля и выбранные значения.
- Новый пользователь получает действующее приветствие после регистрации и входа. Закрытие сохраняется в БД. Замена приветствия администратором не показывает его заново пользователям, уже прошедшим знакомство. Аккаунты, существовавшие до установки функции, приветствие автоматически не получают.
- Обзоры обновлений показываются по одному, каждый выпуск один раз на пользователя. Пользователь видит выпуски, опубликованные с момента создания аккаунта. В «Что нового» доступны последние 100 доступных объявлений. У сотрудников отдельные отметки просмотра.
- Администратор работает в отдельном кабинете `admin.php`, входит через общее окно `login.php`: подтверждённые данные администратора открывают `admin.php`, данные обычного пользователя — `index.php`. Старый адрес `admin-login.php` перенаправляет на общий вход. Это отдельная таблица аккаунтов и отдельный тип сессии, без автоматического назначения прав обычному владельцу бизнеса по номеру телефона.
- Редактор поддерживает русские и казахские заголовки и тексты, MP4/WebM до 100 МБ, предпросмотр, черновики, публикацию, копирование и снятие с публикации. Для публикации обязательны оба языка и видео. Опубликованный текст неизменяем: исправление оформляется новым выпуском.
- Видео хранятся вне web-корня и отдаются через проверку сессии; поддерживаются байтовые диапазоны для перемотки. Воспроизведение начинается по действию пользователя.

## Установка после согласования

1. Сделать резервную копию рабочей базы и файлов. Перенести обновлённые файлы проекта, сохранив приватный конфиг и каталог медиа.
2. Выполнить `php tools/migrate.php`. Миграция создаёт дополнительные таблицы, не удаляя бизнес-данные.
3. Обеспечить запись в `aulieata-media/announcements/` вне `public/`. Другой приватный абсолютный путь задаётся ключом `announcement_media_dir` в конфиге. Этот каталог включать в резервные копии.
4. Настроить PHP: `upload_max_filesize=100M`, `post_max_size=105M`, `fileinfo` включён. Лимит тела запроса веб-сервера и прокси должен быть не меньше 105 МБ. MP4 с H.264 обычно совместим с браузерами; конкретный кодек проверять в предпросмотре. Перекодирование не выполняется.
5. Передать через окружение `AULIEATA_ADMIN_PHONE`, `AULIEATA_ADMIN_PASSWORD` и при необходимости `AULIEATA_ADMIN_NAME`, затем выполнить `php tools/create-admin.php`. После выполнения удалить пароль из окружения. Номер и пароль в репозиторий не записываются. Команда не меняет пароль уже существующего администратора.
6. Войти через `login.php`, заполнить профиль и опубликовать собственное приветствие/обзор. Демо-тексты и демо-видео локального просмотра не устанавливаются на сервер автоматически.

## Проверки

`npm ci && npm test` проверяет PHP/JavaScript, прежние сценарии и регрессию локализации: 23 раздела, 15 вкладок операционного центра, переключение языка, сохранность форм, исходные значения опций, пользовательский контент и обработку ошибки отметки просмотра.

`php tests/announcements.php` требует изолированного локального конфига `AULIEATA_CONFIG` с базой `itu_test_*`, запущенного PHP HTTP-сервера и `AULIEATA_TEST_VIDEO` — пути к небольшому корректному MP4. Проверяет настоящую регистрацию и вход, разделение ролей, отзыв доступа сотрудника, CSRF, загрузку и защиту видео, показ один раз, повторные запросы публикации, снятие с публикации, перемотку и историю более 100 выпусков. Рабочую базу тест не принимает.

Для новых надписей добавлять пару в `i18n-catalog.js`. `I18n.html()` предназначен только для литеральных фрагментов интерфейса из исходного кода: передавать в него уже собранный HTML с пользовательскими данными нельзя. Такие данные экранируются обычным `esc()`.

Дизайн новых экранов подготовлен в [проекте Stitch](https://stitch.withgoogle.com/projects/7099438516525205740). В приложении сохранена исходная палитра, добавлены промежутки между кнопками и адаптация окон к узким экранам.
