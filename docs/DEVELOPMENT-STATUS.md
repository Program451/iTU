## Подключение Instagram

Добавлена карточка в «Подключения»: владелец может сохранить, проверить, заменить и удалить маркер доступа профессионального аккаунта Instagram. Секрет хранится на сервере в AES-256-GCM, не возвращается в ответах API и не сохраняется в браузере. Доступ ограничен владельцем и защищён сессией, CSRF и лимитом запросов. Один Instagram-аккаунт нельзя незаметно перенести между рабочими пространствами.

На рабочем сайте проверены сохранение предоставленного маркера, загрузка подключения после обновления страницы и повторная проверка через Instagram API. Подтверждены профессиональный тип аккаунта и текущий лимит публикаций. Посты, реклама и платные запросы к ИИ при этой проверке не запускались.

На отдельной базе прошли семь групп проверок: шифрование и скрытие секрета, изоляция бизнесов, конфликт аккаунтов, сохранность рабочего маркера при неудачной замене, недействительный маркер и недоступность квоты, запрет действий сотрудников, защита от устаревших результатов параллельной проверки. Повторно прошли HTTP-проверки приложения, синтаксис PHP/JavaScript, каталоги и проверка исходников на секреты.

Это подключение для тестирования по маркеру Meta Developers. Автоматическое продление, OAuth для сторонних бизнесов и нейросетевая генерация фотографий пока не реализованы. Создание карточек и очередь публикаций добавлены следующим расширением ниже. Доступ к лимиту публикаций не означает, что отправка поста проверена. TikTok, Threads и Twitch к приложению не подключены.

## Проверено

- 26 сценариев на отдельной MariaDB 11.4: партии и сроки, FEFO, состав, резерв, списание, отмена, возврат, неизвестная себестоимость, разделение реальных и демонстрационных данных, цены акций по точной партии, лимиты и дата акционного окна.
- Два отдельных PHP-процесса одновременно пытались купить последний товар и занять одно время: в каждом случае успешно только одно действие.
- Связанные заказ и запись согласованно меняют статус; будущий визит нельзя завершить. Перенос обратно восстанавливает отменённое напоминание. Повторная отправка уже доставленного уведомления не создаётся.
- Импорт обновляет по SKU/названию, показывает изменения, сохраняет отсутствующие метаданные и отклоняет применение устаревшего просмотра. Отмена не перезаписывает последующие правки.
- Роли проверяются на сервере при каждом запросе, включая изменение роли и отзыв доступа. Оператор не получает себестоимость, партии, планы и переписку владельца.
- Вход, CSRF, приглашение сотрудника, ограничение действий, отзыв доступа, QR-отзыв, приватность карточки обслуживания, отзыв ссылки и фото проверены через HTTP на локальном сервере.
- Реальные обращения к Gemini: заказ и расчёт по каталогу; план владельца, применение и отмена; передача смены; подбор по бюджету; извлечение прайса; расшифровка аудио. Проверка выполнялась на тестовых данных без отправки клиентам.
- В браузере открыты все 14 рабочих разделов, создан демонстрационный заказ с итогом 2400 ₸. Ошибок JavaScript не обнаружено. Полоса прокрутки бокового меню скрыта, прокрутка сохранена.
- На production: вход и API 200, 24 прежние позиции сохранены; предпросмотр бота обозначает примеры как демонстрационные; план с тестовой задачей применён и отменён, план убран в архив. Telegram webhook доступен, очередь входящих пуста, ошибки доставки не сообщены.
- Обработчик cron.php на хостинге переведён с ежечасного запуска на ежеминутный. Дневные автоматизации сохраняют собственное расписание. Неопределённая доставка помечается отдельно и автоматически не повторяется.

- Голосовой ответ Telegram продолжает использовать sendVoice с MP3. Новый полный цикл с реальным входящим сообщением Telegram после этой публикации отдельно не повторялся; подтверждены распознавание у провайдера, состояние webhook и ранее проверенный способ отправки.
- Настоящая доставка новых напоминаний посетителю проверяется при первой записи с его согласием. Нет утверждения о проверке на всех телефонах и браузерах или полной нагрузочной/безопасностной проверке.
- WhatsApp Cloud API, платежи, Google Calendar OAuth, сбор отзывов 2GIS/Maps, автоматическая Kaspi/1С-синхронизация и отправка в Enbek не подключены. Для них нужны отдельные доступы и интеграции. Поиск грантов зависит от квоты Google Search.

## Контент-студия и очередь публикаций Instagram

- Карточка 1080 × 1350: три оформления, текст, цена/условия, собственное фото; сборка в браузере без внешней генерации. Скачивание JPEG, подпись по шаблону RU/ҚАЗ (без перевода произвольного текста), выбор каталога с явной отметкой демонстрационных данных.
- Только владелец: закрытые черновики, редактирование, предпросмотр точного сохранённого изображения и подписи, выбор подключённого аккаунта и времени UTC+5 до 30 дней вперёд. Публикация требует отдельного подтверждения. Архив восстанавливается.
- Планировщик отправляет подтверждённый снимок поста через Instagram Login API. Проверяет лимит, создаёт контейнер, ждёт FINISHED, сохраняет ID публикации и ссылку при наличии. Отдельная блокировка на пост предотвращает параллельную отправку.
- После начала отправки потеря ответа переводит пост в неопределённый статус: только проверка контейнера, без автоматического повтора. Отправленный/неопределённый пост нельзя вернуть в очередь. Просроченное более чем на два часа расписание останавливается для проверки актуальности.
- Изображения нормализуются GD, хранятся вне public/, выдаются владельцу по сессии. Для Meta создаётся случайная ссылка на 48 часов только после подтверждения и начала подготовки. Токены не попадают в изображения, URL и ответы приложения.
- Проверено локально: восемь групп интеграционных/HTTP-сценариев, включая вход и CSRF, изоляцию пространств, роли, повторный клик, устаревшие правки, UTC+5, отмену, возврат из архива, блокировку через отдельное соединение БД, лимит, истёкшую ссылку, отозванное подключение, успешный ответ, потерю ответа провайдера и отказ базы при записи успешной отправки. Пройдены прежние тесты Instagram, HTTP, PHP 8.1/JS и каталогов.
- Публичные материалы в реальный Instagram при проверке не отправлялись. Полный реальный цикл зависит от разрешения instagram_business_content_publish, действующего токена и требований Meta к приложению. TikTok/Threads/Twitch не подключены. Платные ИИ-запросы этим модулем не выполняются.

На рабочем сайте проверены загрузка редактора, создание JPEG, сохранение и повторная загрузка черновика, приватный предпросмотр и форма подтверждения конкретного аккаунта. Пример поста о проекте оставлен черновиком, без внешней отправки. Перед обновлением сохранены архив файлов и дамп базы вне корня сайта.

Планировщик на production подтвердил свежий запуск после обновления. Отображение времени исправлено: берётся время последнего heartbeat из payload, а не дата создания служебной записи; устаревший heartbeat больше не показывает активный статус.


## TikTok Login Kit

В «Подключения → TikTok» владелец сохраняет Client key и Client secret своего приложения TikTok, затем проходит официальный OAuth-вход. Эта версия подключает и проверяет профиль (`user.info.basic`). Публикация фото/видео, Content Posting API и автоматическое расписание TikTok пока не реализованы. Instagram продолжает использовать отдельную очередь.

Для теста создайте приложение Web в [TikTok for Developers](https://developers.tiktok.com/), включите Sandbox, добавьте свой аккаунт в Target users, продукт Login Kit и scope `user.info.basic`. Внесите Redirect URI `https://ВАШ-ДОМЕН/tiktok-callback.php` в Login Kit и сохраните изменения. Рабочий адрес показывается в форме; для itudron.ru он равен `https://itudron.ru/tiktok-callback.php`. Затем сохраните ключи именно этого Sandbox в приложении и нажмите «Войти через TikTok». [Официальная инструкция Sandbox](https://developers.tiktok.com/docs/en/add-a-sandbox).

Данные приложения настраиваются отдельно владельцем рабочего пространства. Секрет и access/refresh tokens шифруются существующим стабильным ключом сервера. Callback требует текущую сессию владельца и одноразовый state, действующий 10 минут; смена настроек и отключение аннулируют ожидающий вход. Обновление токена выполняется при проверке подключения, если срок близок к истечению; фонового продления нет. Отключение удаляет локальный доступ и запрашивает отзыв в TikTok, при неудаче явно предлагает отозвать разрешения вручную.

Проверка `php tests/tiktok.php` требует локальную БД `itu_test_*`, AULIEATA_CONFIG и запущенный HTTP-сервер. Ответы TikTok заменены тестовым обработчиком: ни реальные входы, ни посты, ни платные запросы не выполняются. Реальную авторизацию следует отдельно проверить на Sandbox после предоставления ключей.

### Исправление проверки токенов TikTok, 18 октября 2026

При возврате OAuth сайт показывал «TikTok вернул неполный доступ». Этот текст возникал в локальной проверке access_token/refresh_token до проверки профиля. Прежнее регулярное выражение разрешало только буквы, цифры и `_.~-`, хотя API описывает токены как строки без такого ограничения. Проверка исправлена: непустой непрозрачный токен до 4096 байт, без пробелов, управляющих и не-ASCII байтов. Значение не изменяется; проверки state, владельца, open_id, scope, сроков, шифрования и уникальности аккаунта сохранены. Отсутствие access/refresh token теперь отличается сообщением от недопустимого формата; значения токенов в ошибки не включаются.

`php tests/tiktok-tokens.php` воспроизвёл прежнюю ошибку на тестовом токене с пунктуацией, а после исправления прошёл. `php tests/tiktok.php` также проверяет пунктуацию при обмене, сохранении, передаче в проверку профиля и ротации; все шесть групп и npm test прошли. Ответы провайдера подставные. Реальный ошибочный ответ TikTok не сохранялся; повторный вход пользователя нужен для подтверждения полного рабочего цикла.

Перед публикацией сохранён site-before-tiktok-token-fix-20261018.zip вне httpdocs. Архив tiktok-token-format-20261018.zip заменяет только public/tiktok.php.

Источники: [TikTok User Access Token Management](https://developers.tiktok.com/docs/en/oauth-user-access-token-management), [OAuth 2.0, opaque tokens](https://www.rfc-editor.org/rfc/rfc6749.html#section-1.4).

После публикации установленный tiktok.php скачан через панель хостинга и совпал с проверенным исходником побайтно; прямой HTTP-запрос обработчика вернул 200 с пустым телом без ошибок PHP. Права файла установлены 0644. При сборке следующих ZIP задавайте Unix external_attr 0100644 явно, чтобы Windows-архив не выставлял 0666.
